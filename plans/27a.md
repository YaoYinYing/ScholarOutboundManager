进入 ScholarOutboundManager Phase 27A：Xray-document-driven outbound specification refactor。

当前背景：

Phase 25A / 25B 已经尝试支持 Xray Hysteria2：

- 25A: hysteria2 parser + Xray hysteria outbound 初步支持
- 25B: sni/servername -> tlsSettings.serverName
       skip-cert-verify -> tlsSettings.allowInsecure
       alpn fail-closed
       obfs fail-closed
       artifact explain-probe 支持 protocol/error-category/marker 过滤

但用户观察代码后指出：

当前对出口节点配置的处理设计不规范，已经偏离原始数据和 Xray 配置模型。继续被动 patch 会越来越复杂、难懂。应参考 Xray 文档重新设计。

这是正确判断。

本阶段目标：

1. 引入以 Xray 官方配置模型为中心的中间规格层。
2. 把 Subscription parser、Internal normalized spec、Xray renderer 分开。
3. 不再在 build_xray_outbound 里直接从 Clash 字段临时拼 JSON。
4. Hysteria2/VLESS/Trojan/VMess/Shadowsocks 都逐步走同一套结构化配置。
5. 保持现有 CLI 行为和 artifacts 兼容。
6. 保持 redaction 安全边界。
7. 不做 live VPS probe。
8. 不改 production Xray/XrayR/x-ui。

参考 Xray 文档事实：

- Xray Hysteria outbound 使用 protocol="hysteria"。
- Hysteria outbound settings 包含 version/address/port，其中 version 必须为 2。
- Xray Hysteria transport 使用 streamSettings.network="hysteria"，hysteriaSettings.version=2，hysteriaSettings.auth 为认证密码。
- Xray transport 配置是独立层，用于描述当前 Xray 实例如何与对端通信。
- TLS/SNI/allowInsecure 等应作为 streamSettings.security / tlsSettings 相关结构建模，而不是散落在 protocol builder 中。

本阶段不做：

- mihomo backend
- external hysteria2 binary
- live VPS probe
- production XrayR mutation
- automatic failover
- GeoIP
- TUI expansion
- real systemd tests

二、新增 Xray spec 模块

新增文件：

scholar_outbound_manager/xray/spec.py

定义 dataclasses：

1. XrayServerEndpoint

字段：
- address: str
- port: int

校验：
- address 非空
- 1 <= port <= 65535

2. XrayTlsSpec

字段：
- enabled: bool = False
- server_name: str | None = None
- allow_insecure: bool = False
- fingerprint: str | None = None
- alpn: list[str] = field(default_factory=list)

语义：
- 对应 Xray streamSettings.security="tls" 和 tlsSettings。
- server_name 映射 tlsSettings.serverName。
- allow_insecure 映射 tlsSettings.allowInsecure。
- fingerprint / alpn 只有 renderer 明确支持时才输出。
- 不支持字段不得默默丢弃，应记录 warnings 或 unsupported reasons。

3. XrayRealitySpec

字段按当前项目已有 Reality 支持抽象：
- server_name
- public_key
- short_id
- fingerprint
- spider_x 等如现有项目需要

如果暂时不想重构 Reality，可先保留 future placeholder，但不要破坏 VLESS Reality 现有行为。

4. XrayTransportSpec

字段：
- network: str = "tcp"
- ws_path: str | None = None
- ws_host: str | None = None
- grpc_service_name: str | None = None
- hysteria: XrayHysteriaTransportSpec | None = None

5. XrayHysteriaTransportSpec

字段：
- version: int = 2
- auth: str

6. XrayProtocolSpec

可以用 union-style dataclasses：

- VlessProtocolSpec
- VmessProtocolSpec
- TrojanProtocolSpec
- ShadowsocksProtocolSpec
- HysteriaProtocolSpec

HysteriaProtocolSpec 字段：
- version: int = 2
- endpoint: XrayServerEndpoint

注意：
- Hysteria outbound settings 是 version/address/port。
- Hysteria auth 不属于 outbound settings，而属于 hysteria transport settings。

7. XrayOutboundSpec

字段：
- tag: str
- protocol: str
- protocol_spec: one of above
- transport: XrayTransportSpec
- tls: XrayTlsSpec | None = None
- reality: XrayRealitySpec | None = None
- warnings: list[str] = field(default_factory=list)

三、从 CandidateProxy 转换为 XrayOutboundSpec

新增文件：

scholar_outbound_manager/xray/spec_builder.py

实现：

build_xray_outbound_spec(candidate: CandidateProxy, tag: str) -> XrayOutboundSpec

按协议分发：

- build_vless_spec
- build_vmess_spec
- build_trojan_spec
- build_shadowsocks_spec
- build_hysteria2_spec

要求：

1. 这个层只负责把内部 CandidateProxy 转为 XrayOutboundSpec。
2. 不直接输出 JSON。
3. 如果字段缺失，抛 ValueError 或返回 unsupported reason。
4. 对无法映射字段 fail-closed，不要 warning 后继续生成危险配置。
5. 所有协议共享 TLS/transport helper。
6. 不打印 secret。

Hysteria2 spec 规则：

输入 CandidateProxy:

- protocol == "hysteria2"
- address -> endpoint.address
- port -> endpoint.port
- password/auth -> hysteria transport auth
- server_name -> tls.server_name
- skip_cert_verify -> tls.allow_insecure
- tls.enabled = True
- transport.network = "hysteria"
- transport.hysteria.version = 2
- protocol_spec.version = 2

如果 obfs / obfs-password:
- fail-closed

如果 alpn:
- fail-closed until explicit renderer support exists, unless implemented with tests.

如果 server_name missing:
- tls.server_name = address
- warning optional

四、Xray renderer

新增文件：

scholar_outbound_manager/xray/renderer.py

实现：

render_xray_outbound(spec: XrayOutboundSpec) -> dict[str, object]

职责：

- 唯一负责输出 Xray JSON。
- 按 Xray 文档结构渲染。
- 不知道 Clash 字段。
- 不知道 CandidateProxy.extra 的原始形态。

实现函数：

render_stream_settings(spec: XrayOutboundSpec) -> dict[str, object]

规则：

1. transport.network 总是输出到 streamSettings.network。
2. TLS:
   - if tls.enabled:
     streamSettings.security = "tls"
     streamSettings.tlsSettings = {...}
   - server_name -> serverName
   - allow_insecure -> allowInsecure
   - alpn/fingerprint 只有支持时输出
3. Hysteria transport:
   - if transport.network == "hysteria":
     streamSettings.hysteriaSettings.version = 2
     streamSettings.hysteriaSettings.auth = auth

Hysteria outbound renderer 输出：

{
  "tag": tag,
  "protocol": "hysteria",
  "settings": {
    "version": 2,
    "address": endpoint.address,
    "port": endpoint.port
  },
  "streamSettings": {
    "network": "hysteria",
    "security": "tls",
    "tlsSettings": {
      "serverName": "...",
      "allowInsecure": false
    },
    "hysteriaSettings": {
      "version": 2,
      "auth": "..."
    }
  }
}

六、Parser 层不要直接“猜 Xray”

修改原则：

scholar_outbound_manager/parsers/clash.py

Parser 只负责：
- 读取 Clash YAML
- 规范化 CandidateProxy 字段
- 保存 raw protocol fields 到 extra
- 做最小 required field validation
- 对已知无法支持的字段标记 unsupported

Parser 不负责：
- 生成 Xray JSON
- 判断 streamSettings 结构
- 写 tlsSettings/hysteriaSettings

Hysteria2 parser 仍可保持：
- obfs fail-closed
- alpn fail-closed if renderer not supported
- server_name/skip_cert_verify supported because spec_builder can map them

九、README

新增开发说明章节：

## Xray outbound architecture

说明三层：

1. Subscription adapters normalize external formats.
2. Xray outbound specs model protocol, transport, TLS, Reality, and Hysteria.
3. Xray renderer emits official Xray JSON.

强调：

- New protocol support should add a spec builder and renderer tests.
- Do not patch Xray JSON directly in parser.
- Do not silently ignore unmapped protocol fields.
- Hysteria2 support follows Xray's hysteria outbound + hysteria transport structure.

Introduce a document-driven Xray outbound specification layer.

This change separates subscription parsing, normalized Xray outbound specifications, and JSON rendering so protocol support is modeled according to Xray's protocol, transport, TLS, and security configuration structure.
