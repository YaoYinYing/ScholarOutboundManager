进入 ScholarOutboundManager Phase 25C：transport retry and warm-up for Hysteria2 probes.

当前背景：

Phase 25A:
- Added Xray Hysteria2 outbound support.

Phase 25B:
- Mapped Hysteria2 server_name/sni to tlsSettings.serverName.
- Mapped skip-cert-verify to tlsSettings.allowInsecure.
- alpn and obfs remain fail-closed.
- Tests passed.

VPS live probe still shows Hysteria2 failures:
- home: SSL error: TLS/SSL connection has been closed (EOF)
- query: SSL error: TLS/SSL connection has been closed (EOF)
- failure_markers:
  - transport_error
  - stage_transport_failed

User observation from desktop client:
- Hysteria2 node connectivity test often times out on the first attempt.
- The immediately following second test often returns latency.
- This suggests cold-start / warm-up behavior.

Interpretation:

Current probe waits only for local SOCKS readiness. That does not prove the Hysteria2 outbound has completed QUIC/auth/TLS state setup. The first Scholar HTTPS request may trigger outbound cold start and fail with timeout or SSL EOF. Desktop clients may hide this with implicit retry.

本阶段目标：

1. Add transport-level retry inside a single candidate probe lifecycle.
2. Add optional Hysteria2 warm-up before Scholar classification.
3. Retry only transport failures, never Scholar semantic blocks.
4. Preserve conservative Scholar classification.
5. Do not mutate production Xray/XrayR/x-ui.
6. Do not add live network tests to unit tests.

关键原则：

- Retry must happen while the same Xray process is still running.
- Do not restart Xray between retries.
- Do not retry google_sorry/http_403/http_429/stage_query_blocked.
- Retry only stage_transport_failed / transport_error / ssl_eof / timeout.
- Keep all attempts redacted.
- Do not print HTML body or proxy secrets.

二、识别 transport-retryable result

新增 helper：

is_transport_retryable_probe_result(result: ProbeResult) -> bool

返回 True if:

- "stage_transport_failed" in result.failure_markers
- "transport_error" in result.failure_markers
- result.timeout is True
- result.error contains:
  - "TLS/SSL connection has been closed"
  - "EOF"
  - "connection reset"
  - "timed out"

返回 False if:

- "stage_query_blocked"
- "stage_home_blocked"
- "google_sorry"
- "automated_queries"
- "http_403"
- "http_429"

三、在 probe_candidate 内实现 retry

当前 probe_candidate 大概流程：

- prepare runtime config
- optional xray -test
- start xray
- wait socks ready
- probe home/query
- classify
- cleanup

修改为：

1. Start Xray once.
2. Wait SOCKS ready once.
3. Optional warm-up if candidate.protocol == "hysteria2":
   - call lightweight HTTP probe via same SOCKS
   - ignore failure except log redacted warmup status
4. Run Scholar home/query attempt.
5. If result is transport retryable and attempts remain:
   - sleep backoff
   - retry home/query using same SOCKS
6. Keep best/final result:
   - If any attempt passed, use passed result.
   - If no attempt passed, use last result.
7. CandidateProbeSummary should include:
   - attempt_count
   - transport_retry_count_used
   - warmup_attempt_count
   - final_attempt_index

If adding fields breaks too much, make them optional/default.

四、CLI probe flags

Add to `probe` CLI:

- --transport-retry-backoff SECONDS

Recommended VPS command for Hysteria2 validation:

scholar-outbound-manager probe \
  --config config.yaml \
  --candidates candidates.json \
  --summary-output state_data/probe_summary.json \
  --passed-candidates-output state_data/passed_candidates.json \
  --parallel 2 \
  --keep-all-passed \
  --query ppr \
  --request-timeout 20 \
  --transport-retry-count 2 \
  --transport-retry-backoff 1.5 \
  --hysteria2-warmup-attempts 1 \
  --allow-network-probe

Note:
- For Hysteria2, use lower parallelism first, e.g. 2.
- UDP/QUIC nodes may behave worse under high parallel cold starts.

十、提交

Commit message:

feat: add transport retries for Hysteria2 probes

Commit body:

Add transport-level retry and warm-up support for Hysteria2 candidate probes.

This change allows retrying transient transport failures such as SSL EOF or startup timeouts within the same managed Xray process, which better matches Hysteria2 cold-start behavior observed in desktop clients. Retries are limited to transport-level failures and do not apply to Scholar semantic blocks such as google_sorry, HTTP 403, or query-blocked classifications.

This phase intentionally keeps production Xray/XrayR mutation, live network tests, automatic failover, GeoIP lookup, and external proxy backends out of scope.
