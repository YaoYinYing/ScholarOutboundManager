进入 ScholarOutboundManager Phase 26A：workflow-oriented Textual TUI with tabs and wizard.

当前背景：

ScholarOutboundManager 已经形成完整的 sidecar-first 使用链路：

fetch subscription
-> candidates.json
-> probe --parallel --keep-all-passed
-> probe_summary.json
-> passed_candidates.json
-> artifact check
-> select list / choose
-> selected_candidate.json
-> sidecar service-stage
-> sidecar service-restart
-> sidecar service-validate
-> service-snippet / pool snippets
-> production Xray/XrayR manual downstream integration

项目当前已经完成：

- Clash YAML parser
- VLESS / Trojan / Shadowsocks / VMess / conservative Hysteria2 outbound support
- Hysteria2 TLS/SNI mapping
- parallel probe
- keep-all-passed
- artifact lineage check
- redacted candidate catalog
- human-readable redacted labels
- region_hint selection
- selected_candidate artifact
- sidecar systemd production mode
- safe sidecar restaging with --skip-xray-binary-copy
- single-Xray multi-port pool
- optional Textual TUI extra already exists in early form

用户现在希望：

TUI 按照文档中的使用步骤，设计成模块化 tab system 或 wizard 模式，指导用户一步步完成节点对接。

核心判断：

TUI 不应只是 CLI 按钮集合。
TUI 应该把文档中的实际 workflow 变成可恢复、可验证、可回退的操作路径。

建议架构：

1. Tab system:
   用于日常运维和检查。

2. Wizard mode:
   用于首次部署、重新 fetch/probe、重新选择节点、重新 stage sidecar。

3. CLI remains source of truth:
   TUI 调用现有服务层或 CLI-safe helper，不重新实现业务逻辑。

4. No secret display:
   TUI 只显示 redacted view model，不展示 sensitive artifact raw content。

本阶段目标：

1. 将 TUI 扩展为 workflow-oriented control surface。
2. 增加 tabs：
   - Dashboard
   - Preflight
   - Fetch & Probe
   - Artifacts
   - Selection
   - Sidecar
   - Pool
   - Troubleshooting
   - Snippets
3. 增加 Wizard：
   - Step 1: Preflight
   - Step 2: Fetch
   - Step 3: Probe
   - Step 4: Artifact Check
   - Step 5: Select Candidate
   - Step 6: Stage Sidecar
   - Step 7: Restart & Validate
   - Step 8: Snippet Export
4. 每一步都显示：
   - 当前输入文件
   - 是否存在
   - 是否 ignored
   - 上一步是否通过
   - 将要执行的命令
   - 安全风险提示
   - 执行按钮
   - redacted result
5. 支持中断后恢复。
6. 不在测试中执行真实网络、systemd、Xray。
7. 不修改 production Xray/XrayR/x-ui。
8. 不显示任何 secret。

本阶段不做：

- 自动修改生产 Xray/XrayR/x-ui 配置
- 自动 reload production service
- Docker
- mihomo backend
- automatic failover daemon
- real live probe in tests
- real systemd execution in tests
- GeoIP egress lookup
- secret viewer

一、依赖边界

确认 Textual 仍然是 optional extra：

[project.optional-dependencies]

    "textual>=..."

要求：

1. core install 不依赖 textual。
2. import scholar_outbound_manager 不导入 textual。

4. 如果未安装 textual，输出：
   Textual TUI is not installed. Install with:
   pip install "ScholarOutboundManager[tui]"

入口保持或新增：

scholar-outbound-manager tui

或者：

四、Tabs 设计

主界面使用 TabbedContent。

Tab 1: Dashboard

显示：

- repo status clean/dirty
- current git commit
- venv detected
- config.yaml exists
- xray binary exists
- service active/enabled
- socks tcp connect
- last Scholar validation
- candidate_count
- passed_count
- selected candidate label
- current sidecar port

不显示 secret。

Tab 2: Preflight

功能：

- 检查 workspace
- 检查 config exists
- 检查 enabled_subscription_count
- 检查 xray inspect
- 检查 git status
- 检查 ignored artifacts

显示类似：

config.yaml: exists, ignored
.runtime/xray/xray: executable
enabled_subscription_count: 1
probe_allow_network_probe: true
routing_fail_closed: true

Tab 3: Fetch & Probe

分为两个 panel：

Fetch panel:

- command preview:
  scholar-outbound-manager fetch ...
- button: Run fetch
- result:
  candidate_count
  supported_count
  unsupported_count
  protocol_counts
  supported_protocol_counts

Probe panel:

- settings:
  parallel workers
  query
  request timeout
  keep_all_passed toggle
- command preview:
  scholar-outbound-manager probe ...
- button: Run probe
- result:
  attempted_count
  skipped_count
  passed_count
  failed_count
  markers_by_protocol
  errors_by_protocol

所有网络动作必须有确认提示：

"This will perform live network fetch/probe from this VPS."

Tab 4: Artifacts

显示：

- candidates.json exists/hash/run_id
- probe_summary.json exists/hash/run_id
- passed_candidates.json exists/hash/run_id
- artifact check result
- warnings for legacy/mismatch

功能：

- Run artifact check
- Run artifact explain-probe
- filter by:
  protocol
  region_hint
  marker
  error_category
  label regex

Tab 5: Selection

显示 redacted candidate table：

columns:

- index
- label
- region
- candidate_id
- protocol
- passed
- stage
- home
- query
- markers

功能：

- search label
- filter protocol
- filter region_hint
- filter passed only
- choose highlighted candidate
- strategy auto
- preferred_region_hint input
- write selected_candidate.json

必须显示：

selected_candidate.json is sensitive and will not be displayed.

Tab 6: Sidecar

显示：

- selected candidate metadata:
  selected_candidate_id
  selected_label
  selected_region_hint
  protocol
- service status:
  active/enabled
- runtime:
  listen_host
  listen_port

功能：

- service-stage with --skip-xray-binary-copy
- service-install
- service-restart
- service-validate
- service-enable
- service-stop

Mutating operations require confirmation:

- service-stage
- service-install
- service-restart
- service-enable
- service-stop

Tab 7: Pool

显示：

- current pool plan exists
- entries
- base_port
- ports
- candidate labels
- protocols

功能：

- build pool plan
- max-count input

- check ports

- pool validate

Tab 8: Troubleshooting

提供常见诊断入口：

- enabled_subscription_count = 0

- Hysteria2 transport failure

每个诊断项显示：

- meaning
- safe command to run
- expected result
- next action

Tab 9: Snippets

显示：

- sidecar service-snippet

五、Wizard 设计

Wizard 以步骤为核心，每一步对应文档流程。

Step 1: Preflight

Checks:

- config exists
- enabled subscription count
- xray binary executable
- git status
- venv available

按钮：

- Run preflight
- Continue only if required checks pass

Step 2: Fetch

Shows:

- command preview
- network warning
- run button

Result:

- candidate_count
- supported_count
- protocol_counts

Step 3: Probe

Shows:

- parallel workers input
- query input
- timeout inputs
- keep_all_passed checkbox

Result:

- passed_count
- failed_count
- marker summary

Step 4: Artifact Check

Runs:

artifact check

Continue only if:

- overall consistent true

If legacy/unknown:

- allow continue with warning
- recommend rerun fetch/probe

If mismatch:

- block continue by default

Step 5: Select Candidate

Shows candidate table.

Options:

- manual selection
- strategy auto
- preferred_region_hint

Action:

- write selected_candidate.json

Step 6: Stage Sidecar

Default command uses:

--skip-xray-binary-copy

If binary missing:

- show warning
- allow source_xray_binary copy only after confirmation

Step 7: Restart & Validate

Actions:

- service-restart
- service-validate

Continue only if:

- scholar_passed true

Step 8: Snippet Export

Show:

- service snippet
- next manual production integration note

六、Command adapter

TUI should not duplicate business logic.

Preferred order:

1. Use internal Python functions when they are pure and safe:
   - build_candidate_catalog
   - artifact consistency helpers
   - selection helpers
   - pool plan helpers

2. Use CLI subprocess wrapper for operational commands:
   - fetch
   - probe
   - service-stage
   - service-restart
   - service-validate
   - pool stage
   - pool validate

Command adapter must:

- capture stdout/stderr
- redact output before display
- store exit_code
- store command preview
- not use shell=True
- support timeout
- be monkeypatchable in tests

七、Redaction requirements

Before anything is displayed in TUI, run through redaction.

Must redact:

- raw_uri
- vless://
- vmess://
- trojan://
- ss://
- hysteria2://
- UUID
- public_key
- password
- token
- auth
- obfs-password
- server address
- server_name
- sni
- IP address
- host

TUI must never display:

- config.yaml content
- candidates.json raw content
- passed_candidates.json raw content
- selected_candidate.json raw content
- runtime config content

八、Testing strategy

Tests must pass without textual installed.

Add tests:

tests/test_tui_workflow.py
tests/test_tui_view_model.py
tests/test_tui_commands.py
tests/test_cli_tui.py

Required tests:

1. importing scholar_outbound_manager does not import textual.
2. `scholar-outbound-manager tui` without textual prints install hint.
3. workflow steps are in expected order.
4. wizard blocks artifact mismatch by default.
5. candidate table rows hide secrets.
6. dashboard model hides secrets.
7. command adapter uses list argv, not shell=True.
8. command adapter redacts stdout/stderr.
9. fetch/probe command preview is correct.
10. service-stage command includes --skip-xray-binary-copy by default.
11. pool plan view shows ports and labels only.
12. snippets view does not contain secrets.
13. session state does not store sensitive fields.
14. no real network.
15. no real systemd.
16. no real Xray start.

If textual is installed in dev environment, optional tests may use Textual pilot, but default test suite must not require it.

Add a workflow-oriented Textual TUI for ScholarOutboundManager.

This change turns the documented VPS workflow into a tabbed and wizard-guided terminal interface. The TUI provides preflight checks, fetch/probe orchestration, artifact consistency review, redacted candidate selection, sidecar staging and validation, multi-port pool controls, troubleshooting views, and downstream SOCKS snippets while preserving the CLI as the source of truth and keeping secrets out of the interface.
